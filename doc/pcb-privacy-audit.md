# PCB 工程隐私审查与脱敏

审查日期：2026-10-26。

对象：`pcb/pico-dualcore-devboard-v1.2/pico-dualcore-debug.eprj2`。

| SQLite 空闲页 | 原有 90 页 | 重建后为 0 页 |

## 已确认的隐私泄露

不能以普通文本搜索未命中作为该工程没有个人信息的依据。

179 段历史数据中，有 151 段明文包含个人账号；对应 160 条文档头用户记录。个人信息主要位于 `DOCHEAD.user` 中，包括用户名、昵称和用户 UUID。`EDIT_HEAD`、工程所有者和成员引用也保留了实际编辑者 UUID。

此外，592 条 `DOCHEAD` 记录含 13 个不同的编辑客户端标识。它们不是硬件探针序列号，但可用于关联编辑活动。工程预览图的旧 API 路径、工程和分支标识也提供了关联原工程的线索。

加密不是隐私隔离措施：解密所需的历史密钥和历史 UUID 同在数据库内。此次依据本机已安装 EDA 程序中的 AES-128-GCM、gzip 和 Base64 存储实现，完整读取了所有数据段，没有猜测密码或绕过账户认证。

## `password` 字段的核实

`users` 中唯一一条记录的用户名、昵称和 `password` 原来都是通用的 `LCSC` 占位值。该记录属于元件库命名空间，不能把它误报为个人账号密码泄露。

脱敏保留了该库命名空间及其来源引用，并将无用途的占位 `password` 清空。没有删除元件库来源或第三方版权声明。

## 已执行的脱敏

- 将所有 `EDIT_HEAD` 和 `DOCHEAD.user` 中的人员身份替换为匿名元数据。
- 替换实际编辑者 UUID，以及数据库中对应的所有者、创建者、修改者、成员和工程结构所有者引用。
- 将 13 个客户端标识替换为匿名值，保持其相对排序，避免改变同票据记录的比较结果。
- 同步替换本工程标识、分支标识和预览图 API 路径中的工程标识，保留它们之间的关联关系。
- 相应更新内部历史表名及本工程来源引用；不改写公共元件库的命名空间。
- 重新编码全部 179 段历史数据，并通过 `VACUUM` 重建数据库，避免旧密文或旧元数据残留在空闲页。

此次没有删掉 EDA 内部设计历史；所有历史数据段均已脱敏。Git 旧提交历史的清理由独立的单提交重建处理。

## 验证结果

- SQLite `integrity_check`：`ok`。
- SQLite `freelist_count`：`0`。
- 179 段数据全部能重新通过 AES-GCM 认证、gzip 解压及源记录解析。
- 逐条比较 38,722 条非编辑头、非文档头记录：除本工程来源标识的同步替换外，记录保持一致。删除标记也完整保留。
- 原理图、元件、走线、焊盘、网络、尺寸及图形数据未变。
- 149 条工程结构记录除所有者字段外保持一致。
- 6 张预览图的内容字节完全一致。
- 5 种嵌入素材没有已知个人账号、本机路径或探针序列号命中；位图均没有 EXIF，SVG 未发现作者或本机导出路径字段。已目视检查位图及预览图。
- 解密内容中的外部 HTTP 链接仅发现元件商城、元件图片/资料和芯片厂商域名，未发现个人站点或带凭据 URL。
- 原个人账号、实际编辑者 UUID、原客户端标识及被替换的工程关联标识未在处理后的相应数据中发现。
- 文件由 8,671,232 字节缩减至 8,474,624 字节。

## 范围与后续注意

本次验证覆盖数据库结构、解密源记录、关联引用、预览图和嵌入素材；没有在 EDA 编辑器中重新打开工程或运行 DRC，不能将结构验证表述为编辑器兼容性实测。

工程内部编辑时间、设计日期、普通图元 ID、公共元件库来源和参考设计图案仍保留。未将它们视为个人账户或设备身份。公开工程内容本身也可能与同一设计的其他副本相互关联。

以后使用登录账户的 EDA 客户端重新编辑保存，可能再次写入账户、客户端和工程关联信息；再次公开前应重新检查加密数据段，而不只检查表层字段。
